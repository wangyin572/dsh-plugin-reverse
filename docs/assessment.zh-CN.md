# 需求评估报告与算法逻辑分析

本文回答两件事：**每条需求到底能不能做到、做到什么程度**；以及**核心算法为什么这样设计**。
判定标准是「宁可说做不到，也不产出一段能跑但算错的代码」。

### 1.2 关于「抹平环境差异」的关键区分

需求里「抹平环境差异」有两种截然不同的含义，混在一起会让工具变成「错误签名生成器」：

| 类型 | 例子 | 静态还原能否处理 |
|---|---|---|
| **依赖可消除** | `document.addEventListener`、`fetch`、`appendChild`、`alert` | ✅ 桩成 no-op，对计算无影响 |
| **值可确定复现** | `atob`/`btoa`、`setTimeout`、`TextEncoder`、`location.protocol` | ✅ 用 Node 真实等价实现，结果与浏览器一致 |
| **值必须采集** | `navigator.userAgent`、`document.cookie`、`screen.width`、canvas/WebGL 指纹、`performance.now()` | ❌ **无法合成**，必须从真实浏览器采集后注入 |

第三类是静态还原的**固有边界**。工具的处理方式是生成 `MUST_CAPTURE` 显式占位
并通过 `createEnv(overrides)` 留出注入点，而**不是**编一个"看起来合理"的值——
后者会得到看起来对、实际错的签名，比直接报错危险得多。

> 这也是明确拒绝引入 jsdom / happy-dom 的原因：模拟器会给出**看似合理但错误**的指纹值，
> 把「算错了」伪装成「算对了」。

### 1.3 关于控制流平坦化不做自动重排

自动重排状态机需要同时确定：状态变量的初值、每个 case 的跳转目标、case 之间的执行顺序、
以及是否存在不可达分支。任何一处判断错误，产出的代码**依然能运行**，只是算出来的结果不同——
这类错误没有任何运行时信号，极难发现。

因此工具的做法是：**报告 `case` 顺序 + 位置**，把置信度降为 `low`，由人决定。
抽出的闭包仍然可用（它包含全部分支），只是需要人工确认执行路径。

### 1.4 明确未实现的部分

| 项目 | 原因 |
|---|---|
| 字符串数组自动内联回使用点 | 轮转偏移往往在运行期确定；未完全还原解码函数前内联等于猜 |
| 状态机自动重排 | 见 §1.3 |
| WASM / 原生扩展中的逻辑 | 超出 JS 静态分析范围 |
| 私钥由 `(n, e, d)` 构造 PEM | 数学上需要 p、q；已提供 `rsa-manual-pow` 作为替代路径 |
| SM2/SM3/SM4 国密 | Node 内置 crypto 不支持；未引入第三方实现以保持核心零依赖 |
| 反调试绕过 | 不属于本工具职责；Hook 脚本仅提供 `toString` 伪装以避免误报 |

## 二、算法逻辑分析

### 2.1 静态还原的四步流水线

```
① 解析        acorn → ESTree，脚本/模块两种模式依次尝试，失败给出带行列的定位
② 符号表      扫描任意深度的声明（混淆代码常把一切塞进 IIFE），同名取范围最大者
③ 依赖闭包    从入口出发，沿自由标识符递归收集；用**源码原文切片**拼装
④ 环境注入    在产出模块顶部插入 `const { window, document, ... } = env`
```

**③ 为什么用原文切片**：不做任何改写，就不存在改写错误。正确性由「是否为原文」这一
简单性质保证，而不是由一套复杂的变换规则保证。

**④ 为什么用环境注入而不是逐点改写**：逐个把 `navigator` 替换成 `env.navigator` 需要
精确定位每一处引用（还要区分引用与属性名），改动点越多越容易出错。注入只需在模块顶部加
**一行**：源码里所有宿主引用自然解析到 `env`。附带的好处是 Node 里没有这些全局，
一旦漏掉某个宿主名，运行时会直接 `ReferenceError` 而不是静默拿到 `undefined`。

### 2.2 自由变量计算与作用域遮蔽

判断「某个标识符是不是宿主引用」需要排除两种情况：属性名（`navigator.userAgent` 里的
`userAgent`）和已被本地声明遮蔽的名字。

- **引用位置判定**：需要父节点与键名，因此遍历器携带 `(node, parent, key)`，
  排除非计算成员访问的 `property`、对象字面量的非计算 `key`、标签名、声明名。
- **遮蔽判定必须是作用域级的**：早期实现把全文件的声明名合成一个扁平集合，
  结果任何一处 `var navigator = …` 都会让全文的 `navigator` 都不再被识别为宿主引用。
  这是**危险的漏检**（漏掉的环境依赖会让还原结果悄悄算错），现已改为
  「文件根 + 每个函数」各一个作用域集合，按包含关系逐层体检。

### 2.3 环境值三分类

`src/analysis/host.ts` 维护一份约 60 项的宿主全局目录，每项标注
`removable` / `capturable` / `must-capture` / `diagnostic`。分类决定生成的桩：
可确定复现的给真实实现，纯副作用给 no-op，必须采集的给显式占位。

### 2.4 宿主引用的函数归属

报告「哪个函数在碰环境」对定位入口极有价值（签名函数通常要读环境）。归属判定用
**区间包含**：预先收集全部函数范围，对每个引用取「包含它的最小函数」。
早期实现用遍历时维护函数栈，但遍历器只有进入没有退出回调，栈永远不回退，归属必然出错。

### 2.5 安全重写的三条铁律

1. **只做可证等价的变换**：字符串转义还原用的是 AST 已解码的 `value` 重新序列化，
   是同一个值换一种写法；常量折叠只处理 `!0`/`!1`/`void 0`/字面量拼接这类可证情形。
2. **替换范围必须覆盖完整语法单元**：把 `obj['abc']` 改成 `obj.abc` 时，范围要含
   结尾的 `]`（否则产出 `obj.abc]`），也要覆盖开头的 `[`；可选链 `a?.['b']` 必须保留 `?.`。
   两处都曾有 bug，现由回归断言锁住。
3. **嵌套替换取更宽者**：`!![]` 会同时规划出「整体 ⇒ `true`」和「内层 ⇒ `false`」，
   按 `end` 降序应用才能保证更宽的匹配优先；按 `start` 降序会产出 `!false`。

### 2.6 密码学核心的兼容性设计

前端 AES 几乎都来自 CryptoJS，而它有三个不成文的默认行为，不还原就会「算法对了却解不出来」：

1. 传字符串口令时走 OpenSSL 的 `EVP_BytesToKey` 派生子密钥；
2. 派生摘要默认是 **MD5**（不是 SHA）；
3. 密文带 `"Salted__" + 8 字节 salt` 前缀，再整体 base64。

因此核心提供了 `passphrase` 模式、可切换的 `kdfHash`、以及 `opensslDecrypt`/`opensslEncrypt`
一对函数。正确性用**系统 OpenSSL 现场生成的向量**校验，而不是自造自验。

RSA 覆盖两条路径：PEM 的标准库路径，以及混淆代码里常见的手写大数路径
（`m = c^d mod n`，用 BigInt 实现 `modPow`），后者不需要 PEM 即可复算。

### 2.7 分层与依赖方向

```
tools → services → analysis → core
```

`core` 零宿主依赖，因此它本身就可以被复制到任何 Node 项目里单独使用；
它遵循的约束与「插件产出给用户的纯算代码」完全一致——插件自己的核心就是这套标准的示范。
